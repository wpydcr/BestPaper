# 项目经验记录

沿用当前项目已有经验文档；没有时再建立，例如LESSONS.md或经验教训.md。不要把别篇技术结论或本项目具体事实写入全局CLAUDE或共享BestPaper。

一条有用教训记录：发生情境和目标；原句/版本/源记录；错误决策及根因；影响哪些读者判断；实际改法；在哪些条件下适用；按原失败情境验证的结果；尚未确定之处。

旧教训可能失效，保留原前提并说明新证据为何改变它。新增条目不能替代本批全部受影响修改的复查；无新根因不编造教训。

可迁移机制另列为BestPaper更新建议，例如“不能把审计者补出的逻辑算作原稿已有逻辑”“删术语也可能制造长描述”“保义不能代替可读性”“删句先核职责承接”。包含证据与适用边界，去掉项目术语、数据、技术裁定和局部阈值。只有获授权的技能维护任务落实共享更新。
