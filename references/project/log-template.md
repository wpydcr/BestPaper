# BestPaper 当前状态

这是可按需采用的简短状态格式。优先延续项目已有日志；字段用于恢复真实工作，不是填表验收。不要搬入论文正文。

```yaml
status: active  # active / waiting_for_author / paused / completed
stage: revision  # planning / revision / audit / blind_review / substantively_converged / polish / delivery
input_version: 实际文件或提交标识
authorization: 本轮已授权范围；保留审批的对象
reminder: 当前环境、已启用/未启用/已暂停、会话或automation标识
```

## 本轮目标

说明目标读者应更清楚地理解哪项已有价值，当前稿在哪里没有做到。写明实际输入和最终交付位置。

## 下一步及必要待办

只记录会改变决定的证据缺口、已授权的下一项动作、尚未处理的收到意见及依赖。不要凭文件名变化重启已做完的工作。当前用户要求优先。

## 改稿决定与效果

按批简记：原文位置、承担的职责、独立理由、实际改法、独立复核结果与依据、修改后的读法及未核验范围。可链接已有报告，不复制整份历史。长处和改善先写，不能只报缺陷数量。

所有收到的评审意见须有处置：成立的问题、表达误读、评审自身错误、范围或偏好。旧裁定不是跳过分析的理由；不采纳要有依据。

## 验证与阶段结果

记录当前版本实际检查了什么及结果，区分：

- 已验证：有当前产物和核对证据；
- 按作者安排跳过：未在本轮核验，明确范围；
- 待处理或待作者决定：具体缺项及影响。

独立审计、冷读和对比盲审分开记录。盲审附本稿版本、池与样本、呈现顺序、输入范围、实际隔离状态、未解决问题及下一阶段。已停止新增盲审时仍保留已收意见的处理状态。

## 本轮专项与证据复用

按有意义的批次记录：改变了什么判断；哪些S项受到影响；对应主专项；本轮核验范围；复用的旧证据及依赖未变的依据；尚缺材料。无需为所有80项反复填写空表。具体检查结果链接原报告，避免多处维护通过状态。

纯机械微改只记实际差异、必要渲染与交付版本核对。一个实质候选的D01可由相关独立专项承担，不重复全文。

## 历史与经验

每个项目维护自己的经验文档，优先沿用已有名称；本日志仅链接条目和本轮事件，不复制全部教训。历史记录是证据，不自动成为新稿的约束。新经验要写清下一批在哪个动作点检查，迁移通用根因而不是另一篇论文的技术结论。前提错误影响的任务停止重启。

## 实质收敛与人工润色决定

模型有依据判断实质收敛时可以停止，将stage记为substantively_converged、status记为waiting_for_author，提交当前完整稿、判断依据、已完成及未完成的检查范围，并停用提醒。此状态不代表完整生命周期已经完成。

最后润色须记录作者的明确安排后再启动或继续；没有人工决定就保持暂停，定时提醒不能代替授权。

## 交付或暂停

写明作者实际拿到的文件、核对版本与内容、未验证项、当前提醒停用结果，以及恢复时需要知道的下一步。不要把跳过的工作标为验证通过。
