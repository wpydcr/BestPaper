# BestPaper 自动循环提醒

提醒只服务于正在运行的、已授权的自动循环。**进入循环时启用，循环结束时停用。** 读技能、单次修改、单次审计和普通工具调用不构成进入循环。这里的自动循环是主会话在已授权范围内自主修订、核验并进行必要后续轮次；不因此取得新增盲审、最后润色或外部发布授权。

开始前记录循环范围、实际稿件和停止条件；模型判断实质收敛、作者叫停、暂停等待决定、交付或转任务时结束或暂停循环并停用提醒。恢复时先核授权，再显式恢复。提醒正文在reminder.md，只维护一个版本。

## Claude Code

正式调用 `/BestPaper` 或Skill工具才注册技能级PostToolBatch hook；单独Read文件不注册。注册不等于启用：首次工具批只提供真实session_id/cwd并建立inactive状态，不开始计时，后续普通工具调用也不会自动启用。

主会话进入已授权自动循环时，用实际会话ID和绝对项目目录显式运行arm；该命令核提醒正文、绑定当前会话/目录，并从启用时刻开始默认1800秒计时。取得成功回执后才称已启用。循环结束运行disarm。停用后的工具调用不会自动恢复；下一次循环须重新arm。

本次升级使用独立的v2状态目录，保留旧v1文件但不继承其active状态。旧版曾由首次工具调用自动启用，不能据此认定新规则下已进入循环；升级后需要在真实循环入口重新arm。

到期提醒在下一工具批结束、下一模型请求之前注入；纯思考、没有工具或长工具尚未结束时，不保证按时钟到点触发。技能级hook不修改全局settings，子代理不启用本机制。状态在系统临时目录，不保存论文正文。

新用户消息先暂停旧循环提醒。主会话判断确实继续同一已授权自动循环后显式arm；普通问答、单次修改或新任务保持停用。SessionEnd静默停用。重新调用技能、恢复旧聊天或读到旧active状态，都不能替代循环授权与实际状态核对。

下面的<skill-directory>替换为实际技能目录；ID和cwd取真实hook注册回执，不能猜：

```text
python "<skill-directory>/scripts/reminder.py" status --session-id '实际会话ID' --cwd '实际绝对项目目录'
python "<skill-directory>/scripts/reminder.py" arm --session-id '实际会话ID' --cwd '实际绝对项目目录'
python "<skill-directory>/scripts/reminder.py" disarm --session-id '实际会话ID' --cwd '实际绝对项目目录'
```

需要Python 3。hook默认使用PATH中的python；环境仅提供python3时调整command。本地可用核实的解释器路径，但个人路径不提交共享配置。`${CLAUDE_SESSION_ID}`若仍是占位字符串就不是真实ID；不得拿它arm。

新安装可能需重新正式调用技能或在新会话注册；没有实际注册与arm回执就不报启用。管理策略拒绝或脚本失败时报告限制，不修改安全策略绕过。停用逐文件处理；坏状态不阻止其他可验证状态停用。检查标准错误与实际状态，退出码0不证明全停用；“停用未全部确认”须报告具体缺口，不覆盖坏状态或重新授权。

status只说明保存状态，不证明模型已收到提醒。真实注入要看additionalContext与后续行为；短间隔测试不能称真实30分钟验收。

## Codex desktop

仅在主会话进入已授权自动循环时，使用可用的automation_update创建或恢复绑定当前论文聊天的heartbeat。先查同类“BestPaper执行纠偏”提醒，已有则复用；间隔30分钟，prompt使用reminder.md并补本循环的项目、稿件、范围、停止条件及状态文件位置。不得在读技能或普通改稿开始时创建，不另开独立cron任务。

取得工具成功回执及实际状态后才说启用，保存automation ID。循环结束立即用同一工具暂停该提醒，等待作者、暂停或转任务也暂停。恢复同一循环或进入新的已授权循环时再明确恢复，不由定时唤醒重开已结束循环。提醒触发时先核循环状态；若已结束或暂停，只完成停用，不继续改稿。

使用工具当前schema，不手写automation.toml。工具不可用时执行动作节点检查并报告未启用自动提醒，不用后台sleep或UI按键冒充。heartbeat与Claude工具边界hook时序不同，都不保证中途打断生成。本次技能维护不等于进入论文自动循环，不给维护聊天挂论文提醒。
